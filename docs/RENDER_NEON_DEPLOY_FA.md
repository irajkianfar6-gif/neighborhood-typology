# استقرار آزمایشی رایگان: Render + Neon + Cloudflare Worker

## اجزای آماده

- `render.yaml`: یک Web Service با Docker و `plan: free`؛ هیچ دیسک یا پایگاه دادهٔ پولی Render ساخته نمی‌شود.
- `Dockerfile`: Node 24 هم‌نسخهٔ اصلی با CI، Python در محیط مجازی، وابستگی‌های kernel و Poppler برای خواندن PDF. رابط Vite در تصویر ساخته می‌شود و Express همان رابط و API را ارائه می‌کند.
- پورت Render با `SCI_PORT=10000` تنظیم می‌شود؛ برنامه صرفاً از `PORT` استفاده نمی‌کند.

## اتصال پایگاه داده

در Render، `DATABASE_URL` را فقط از طریق تنظیمات محرمانهٔ سرویس وارد کنید. نشانی اتصال را در مخزن، لاگ یا متغیرهای `VITE_` ذخیره نکنید. برای قفل مشورتی همگام‌سازی فایل‌ها از اتصال مستقیم Neon استفاده کنید، نه اتصال transaction-pooled با `-pooler` در hostname.

طرح‌واره‌های موجود مخزن باید در پایگاه دادهٔ تازه اعمال شوند:

1. `neighborhood_typology/sql/schema.sql`
2. `neighborhood_typology/sql/zz_ara_runtime.sql`
3. `neighborhood_typology/sql/zz_ara_agentic.sql`

فایل اول را روی پایگاه دادهٔ دارای جدول‌های موجود بدون بررسی دوباره اجرا نکنید. سرور بخشی از جدول‌های همگام‌سازی را نیز با `IF NOT EXISTS` می‌سازد. پس از راه‌اندازی، فعال‌بودن ذخیره‌سازی و نبود خطای پایگاه داده در `/api/agentic/system/storage` بررسی شود.

## اتصال Cloudflare

پروژهٔ فعلی Cloudflare از نوع **Worker** است، نه Pages. بعد از موفقیت API:

- Worker → Settings → Build → Build variables and secrets
- `VITE_API_BASE_URL` = مبدأ HTTPS واقعی Render، بدون `/api` انتهایی
- Build و Deploy مجدد فرانت‌اند

نشانی Render را حدس نزنید؛ از نتیجهٔ ساخت سرویس دریافت کنید. `ARA_ALLOWED_ORIGINS` در Blueprint روی مبدأ Worker فعلی است؛ در صورت تغییر دامنه، مقدار را به‌روزرسانی کنید.

## کنترل پذیرش

1. `/api/health` باید JSON سالم برگرداند.
2. سرویس Python/kernel جداگانه بررسی شود؛ سلامت HTTP به‌تنهایی کافی نیست.
3. POST تحلیل محله به API واقعی برسد، نه فایل‌های استاتیک Cloudflare.
4. ذخیره‌سازی PostgreSQL فعال باشد و یک بازراه‌اندازی آزمایشی داده را بازیابی کند.
5. فایل‌های بزرگ، حافظهٔ نهان و خروجی‌های خارج از همگام‌سازی تضمین پایداری ندارند؛ قبل از ورود دادهٔ واقعی پشتیبان‌گیری و ذخیرهٔ فایل مستقل بررسی شود.

## محدودیت‌ها و امنیت

Render Free کم‌حافظه است و هنگام بی‌استفاده‌بودن می‌خوابد؛ OCR، پردازش ماهواره‌ای و تحلیل هم‌زمان ممکن است به منابع بیشتر نیاز داشته باشند. این پیکربندی تضمین اجرای دائمی تمام قابلیت‌ها نیست. حد و وضعیت پلن Neon را از حساب خود بررسی کنید.

کد فعلی پروژه احراز هویت API را عمداً باز گذاشته است؛ هر کاربر اینترنتی می‌تواند به عملیات نوشتن و امکانات مدیریتی دسترسی داشته باشد. CORS جای احراز هویت نیست. این فایل سیاست امنیتی موجود را تغییر نمی‌دهد؛ قبل از استفادهٔ واقعی، کنترل دسترسی باید جداگانه تصویب و پیاده شود. کلیدهای پولی هوش مصنوعی را به سرویس عمومی بدون کنترل دسترسی اضافه نکنید.
